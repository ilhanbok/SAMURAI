Behavioural notes

  • Orientation. Mode (i) works on np.flip(np.transpose(get_fdata()), 0) and inverts that transform before saving, exactly as the desktop script does. Mode (ii) works in native orientation along the axial (third) axis, as the RAW/QSM wrappers do.
  • Annotation frame. The desktop script prompts SAM2 at slice − 1 to line up with ITK-SNAP's 1-based numbering, while displaying slice. The portal prompts the slice it is showing you; set SAMURAI_ITKSNAP_OFFSET=1 to restore the old offset.
  • Propagation. Forward then reverse propagate_in_video, the same two passes and the same last-write-wins ordering as the scripts. Raw logits are kept so the threshold slider behaves as it does in MultiViewMaskEditor.
  • Threshold CSV. Same COMs_x,COMs_y,COMs_z,volumes layout as the desktop pipeline, one row per label with row 0 as background (skipped when the candidates are listed, as thresholdSAM_01062025.py does). The desktop wrappers write range(0, num_features) and so silently drop the highest label — one lesion per scan; the portal writes range(0, num_features + 1) instead, which is a superset of the old file and keeps row i = label i.
  • Lesion prompts. Each candidate contributes the voxels of its largest slice, sparsified at η = 0.2, as foreground points; propagated logits are binarised at 2.0. Both values are the desktop defaults and both are adjustable in the form.
  • DUPLICATE. The CLI version of this utility references an undefined output_file and cannot run; the portal's version takes the output path it was always meant to take.
  • Working directory. Each browser session gets its own workspace under webapp/workspaces/, playing the role of scripts/. Intermediates (thresholded, labelled and mean-value volumes, the JPEG stack, points and times files) land there and are listed for download. Sessions expire after SAMURAI_SESSION_TTL seconds.

Standard operating protocol

The full protocol lives in scripts/SAMURAIWorkflow.md. In short:

  1. Collect output. Mode (i) produces output_SAMURAI_[yyyymmdd-hhmmss].nii.gz plus a times_SAMURAI_*.txt; mode (ii) produces one [csv]_240_lesionnum_<n>.nii.gz per approved lesion plus the summary CSV.
  2. Inspect before curating. Load the source scan as a base layer and the mask as an overlay in ITK-SNAP or Flywheel, and check all three cardinal planes.
  3. Curate. MERGE the per-lesion files, then ZERO spurious slice ranges and DUPLICATE where a slice was missed.
  4. Hand-finish. SAMURAI captures edges and gradients well but can be overzealous around a lesion; trim with a freehand polygon and voxel painting, respecting the model's boundaries before making drastic changes.
  5. Analyse. VOLUME for mask volumes, IRV for agreement between raters or sessions.

SAMURAI is a tool, not a radiologist. Apply clinical discretion and expert review before interpreting any output. This software is not intended for clinical use.
